# 创作规划

为 SillyTavern 独立生成写作规划，再把规划加入本轮正文请求。规划和正文可以使用不同的 API、模型及预设。

**当前版本：0.5.3。** 测试仓库为 [CZGHCS](https://github.com/Zyzyzy-Dev/CZGHCS)，正式发布仓库为 [CZGH](https://github.com/Zyzyzy-Dev/CZGH)，包含完整源码。已有用户反馈规划与正文生成成功；自动化和模拟浏览器测试不能代替不同酒馆版本、模型及插件组合的实测。

## 工作方式

```text
发送消息 / 重新生成 / 生成新备选
                 ↓
读取规划端选中的预设、世界书、聊天和兼容资料
                 ↓
           调用规划 API
                 ↓
      提取并校验完整规划标签区块
                 ↓
自动继续正文 / 等待点击「生成正文回复」
                 ↓
把规划加入酒馆本轮正文上下文，调用正文 API
```

- **规划配置独立。** 插件中的开关和方案不会修改酒馆原预设、世界书开关或正文 API 连接。
- **正文保留原配置。** 插件在本轮正文请求中追加规划及正文引导，不用规划预设覆盖正文预设。原预设要求的状态栏等成品仍由正文阶段处理。
- **每轮重新规划。** 新消息、重新生成和生成新备选都会重新请求规划；仅查看已存在的备选不会调用 API。
- **规划不等于执行保证。** 标签校验可以拦截不完整、嵌套、空区块及接口明确报告的截断；不能保证模型逐字复述或完成每个自然语言步骤。

## 安装与更新

在酒馆「扩展」中使用「安装扩展」，填入本仓库地址：

```text
https://github.com/Zyzyzy-Dev/CZGH
```

安装或更新后刷新酒馆页面，从魔法棒菜单打开「创作规划」。本仓库关闭自动更新，请手动检查更新。已经安装本仓库的用户直接更新即可，不需要重复安装副本。使用过 CZGHCS 测试版的用户，请勿同时启用测试版与正式版，以免重复拦截生成；更换安装前保留自己的配置和密钥。

扫描核心基于 SillyTavern **1.18.0**。这表示代码适配基线，不表示所有版本和第三方插件组合均已验证；发布反馈请附酒馆版本。

## 首次使用

1. 打开面板，点击齿轮进入设置。
2. 在「通用设置」选择规划 API 方案，核对模型、最大输出和超时。
3. 在「预设」页选择用于规划的酒馆预设，设置分组和条目开关；需要复用时新建方案。
4. 在「世界书」页核对参与规划的世界书及条目。
5. 根据需要开启「流式输出规划」和「在用户消息下显示规划」。
6. 勾选「启用创作规划」，返回聊天发送消息。

默认关闭插件、流式规划和楼内显示；默认开启规划完成后自动生成正文。点击面板右上角关闭按钮或面板外的遮罩只会收起界面，**不会禁用插件，也不会停止生成**。

## API 方案与附加参数

支持三类来源：酒馆当前连接、预设更新编辑器提供的 API 方案、插件自有 API 方案。下拉框中的外部方案直接显示原名称。

- 酒馆当前连接和编辑器方案只读，可以复制为本地方案。
- URL、Key、模型及附加参数的编辑属于方案草稿。点击「新建」或「覆盖」才保存并用于后续请求；编辑后直接关闭面板不等于保存。
- 「覆盖」「删除」仅用于插件自有方案，不修改编辑器原方案。
- 覆盖时 Key 留空会保留已有密钥；新输入的 Key 在保存成功后清空显示。
- 「最大输出」「超时秒数」「流式输出规划」是插件设置，修改后独立保存。
- 附加参数支持 YAML 格式的「包括主体参数」「排除主体参数」「包含请求标头」。不能覆盖规划消息、模型、流式、输出额度或认证等受保护字段。
- 方案选择会记忆。已删除或失效的方案不会自动回退到其他连接。

新输入密钥保存在**当前浏览器、当前酒馆网站地址的 IndexedDB**，方案设置只保存引用。不随普通酒馆设置备份同步到其他浏览器或设备；清除网站数据会丢失密钥。该存储不是加密保险箱，同源脚本及拥有浏览器数据访问权限的人仍可能读取。插件不会把密钥写入聊天或请求预览。

## 预设与世界书

「方案」可载入当前酒馆配置，或选择已保存的插件方案。当前酒馆配置不能被覆盖；载入后可另存。预设和世界书分别记忆所选方案，修改后显示保存状态。

**预设分组：** 关闭分组只阻止读取该组，不改变组内条目的开关；重新开启后恢复各条目原有选择。兼容柏宝箱的预设分组显示，视觉分组不改变原有 prompt_order 执行顺序。点击条目空白区域查看内容。

**世界书：** 按来源显示世界书，展开后查看条目；可以额外添加世界书。开启只表示允许参与扫描，不代表一定注入。支持蓝灯常驻、绿灯关键词及作者注释之前/之后、示例消息前/后等已适配位置。作者注释位置仍遵守启用状态、间隔和深度。

规划端采用隔离的世界书扫描状态，不修改酒馆原生扫描状态；支持的扫描规则包括主次关键词、递归、概率、预算、深度、分组及计时。

### 数据库记忆（龙血玄黄·数据库）

**开启「数据库」后自动处理，不需要选择兼容模式。** 数据库先调用 API 召回并把编码写入用户输入时，规划在该发送前处理完成后，按编码触发世界书绿灯条目，读取详细纪要；没有编码召回时，自动从导出的纪要中筛选相关记忆。两条路径不叠加，插件不会另发一次召回 API 请求。

规划保留在 CHAT_COMPLETION_SETTINGS_READY 阶段执行并重新读取聊天和世界书。所核对的数据库 naiv1.2.9 在更早的 GENERATION_AFTER_COMMANDS、USER_MESSAGE_RENDERED 或 WORLDINFO_ENTRIES_LOADED 阶段等待召回和写回，酒馆 await 这些阶段后才进入规划。因此依靠实际发送流程顺序等待，不设猜测性的延时，也不会在发送开始时因暂时没有编码就提前筛选。对不阻塞发送且不提供完成信号的其他脚本，不能套用这一时序保证；正文最终请求中的模板改写不在本次兼容范围。

自动识别使用本轮用户输入中的完整 `<recall>…</recall>` 块（包括空结果），或与可用纪要关键词对应的 AM 数字编码。识别后走普通世界书扫描，保留条目启用、关键词、概率、深度与预算规则，不受相关纪要条数限制。本轮召回块未闭合、嵌套或结束标签不匹配则停止，避免使用半成品。旧楼层的编码不会切换本轮读取方式；仅蓝灯状态不会被误当作编码召回。

旧版保存的手动读取模式和条数设置自动移除。若旧版已开启数据库并指定独立来源，该来源会迁移到「插件开启的世界书」；私有关闭设置保留。

世界书页固定显示「聊天附加世界书」，位于「插件开启的世界书」前；支持原生单本名称及多本名称数组。

在「设置 → 插件兼容 → 记忆插件」开启 **数据库** 即可。来源统一使用世界书页面的全局、角色、聊天附加、用户角色及插件开启的世界书；关闭的书不参与读取，无需再单独选择数据库来源。支持用户脚本引用的 [naiv1.2.9](https://github.com/AlbusKen/shujuku/tree/naiv1.2.9) 所导出的普通文本纪要。

无编码召回时的筛选实现参考[构画的数据库读取方式](https://github.com/atonal519/ST-SevenDaysCal/blob/98053ee/business/memory/database.js)，从上述启用世界书识别 `TavernDB-ACU-CustomExport-纪要-数字`、`总结条目数字`、`小总结条目数字`，支持 `ACU-[隔离码]-` 和 `外部导入-` 前缀。使用当前用户输入和最近 6 条可见 AI 回复检索（每条清理标签后保留末尾 700 字符，查询最多 6000 字符）。对名称、关键词、纪要正文进行中文双字及英文词重合评分；长度至少 4 的词项计 2 分，其余计 1 分。同分优先世界书中靠后的条目，选中后恢复原顺序。多本世界书的候选合并评分、去重来源后合计最多读取 25 条，不额外调用 API；编码召回不套用此条数上限。历史清理采用构画默认策略，保留 content 内正文；不会读取构画插件的私人设置。纪要无需原生蓝绿灯命中；规划端明确关闭的书或条目仍不读取。

来源和条目开关统一在规划「世界书」页管理。采用相关性筛选时，各启用来源的纪要交给该来源处理，不再通过普通世界书重复扫描；其他状态表、人物等条目仍沿原有世界书规则使用。识别到本轮召回编码或关闭数据库兼容时使用普通扫描。没有可用纪要时正常规划，不额外读取未挂载的书。

预览请求的「资料来源」中，`databaseMode` 表示本轮 keywords（编码触发）/ranked（相关纪要筛选）/disabled 路径，`databaseReason` 记录原因：recall-block 为完整召回块，matched-codes 为可用纪要编码，no-recall-signal 为未发现信号而走筛选，disabled 为未启用。`database` 列出实际采用的数据库条目，`plugins` 中的 `database_memory` 表示使用了独立纪要来源；总输入仍受规划上下文预算限制，超限会明确报错，可在世界书页关闭不需要的条目。

不调用数据库更新/写表接口，不读取原始全表。不执行数据库自己的交火召回，不包括查询/条件模板和零层模式。实际采用的已识别数据库条目若仍含查询或条件模板，会明确报错；请改为普通文本导出或关闭该条目。自行更名的条目可能无法识别；没有导出世界书时不会直接读取内存表格。

## 自动与手动生成正文

在「设置 → 高级设置」切换「规划完成后自动生成正文」。

| 模式 | 规划完成后 |
| --- | --- |
| 勾选 | 自动将规划加入本轮正文上下文并继续生成 |
| 不勾选 | 显示等待状态，点击面板或楼内的气泡图标「生成正文回复」才继续 |

手动模式保留酒馆当前这轮生成流程，等待时酒馆可能仍显示生成中，**但正文 API 尚未调用**。等待时间不计入规划请求超时，重复点击不会重复放行。等待状态不跨页面刷新保存。

等待期间修改消息正文、角色/名称、当前备选，或增删、重排楼层，会让旧规划失效；切换聊天也会取消待用规划。其他插件只更新消息附加数据不会误触发该判断。续写使用本轮开始时冻结的资料和配置，不会在点击按钮时重新读取整个预设、世界书或变量。

### 如何停止

- 规划生成中或等待手动正文时：使用插件「停止本轮」，取消本轮规划及尚未发出的正文请求。
- 正文已经开始后：使用**酒馆自己的停止生成按钮**，插件停止入口不承担正文停止功能。
- 取消勾选「启用创作规划」后：后续请求直接走酒馆原流程。若当时正在规划或等待正文，会取消该轮，需要重新发起。

## 楼内显示、预览与窗口

开启楼内显示后，最新用户消息出现时就显示规划栏，可展开查看流式内容和错误。仅为最新用户楼层渲染面板，减少长聊天中的界面开销。

正文成功后，规划记录写入该回复的 `extra` 并与备选关联，不改写消息正文，也不作为普通历史文本再次发送。历史记录不会被自动删除；部分规划和错误仅在当前页面保留。

眼睛图标打开独立预览，再次点击关闭：

- **生成结果：** 查看最近一次规划输出。
- **发送上下文：** 查看插件交给酒馆后端的实际 messages，以及来源、模型、流式设置和输出额度。酒馆后端仍可能继续转换请求，这不是模型供应商的最终收包日志。
- **预计输入 tokens：** 启发式估算，仅供参考，不是接口实际用量或计费数。
- **压缩同类消息：** 仅合并预览中相邻、同角色且没有额外属性的文本消息，不改变实际请求。

预览可能含私人聊天，不含插件的鉴权头和密钥字段；切换聊天清空本轮请求预览。对外分享截图或日志前请自行检查内容。

拖动面板右下角可调整大小，关闭再打开保留本页尺寸，刷新恢复默认。点击面板外可关闭。外观按钮在自适应、日间、夜间之间循环，楼内与面板同步。

## 自定义提示词与模板

「设置 → 高级设置 → 内置提示词设置」提供两个编辑入口：

- **插件内置提示词：** 发送给规划 API 的引导。
- **注入正文上下文提示词：** 随规划加入正文请求的引导。

默认文本可完整编辑。点击「完成」保存；「取消」放弃草稿；「恢复默认」先替换编辑框内容，再点「完成」才生效。升级时仅自动更新完整匹配旧默认值的规划提示词，自定义文本保留。

规划标签要求与实际规划由插件自动附加，无需插入宏。标签默认从当前规划预设识别，缺失或有歧义时停止，可在高级设置手动指定。

「提示词语法」内可开启 EJS 模板兼容，需要安装 ST-Prompt-Template。模板脚本可能修改变量，不是只读沙箱；插件不主动执行 MVU 生成后的解析回写。

## 兼容范围与限制

- **API：** 当前连接接入已核对的 OpenAI-compatible 返回路径（custom/openai/openrouter/groq/deepseek）；外部 API 方案支持 custom。其他连接明确报错。
- **聊天：** 以单角色文本聊天为范围。群聊轮换和原生附件转换尚未支持；quiet、impersonate、continue 和工具轮次不触发规划。文本正文中的状态栏不属于附件。
- **世界书：** outlet、向量扫描、自动化、角色标签过滤及第三方 WORLDINFO_SCAN_DONE 钩子等未完整适配。已识别的不支持项会阻断，不能宣称与原生注入完全等价。
- **插件资料：** 已接入柏宝书、构画的相关公开资料接口，不额外触发这些插件生成。未勾选的兼容来源不读取。
- **宏与变量：** 已覆盖基础角色/用户/历史值、部分变量宏、柏宝书宏和酒馆助手变量快照。未知双花括号按字面保留；已知宏数据缺失、变量名非法或宏未闭合仍可能阻断。EJS 动态激活指令等未完整适配。
- **MVU：** 尚无完整的真实变量角色卡兼容验收，不保证所有 MVU/EJS 卡可用。
- **额度：** 资料预算使用所选规划预设额度和酒馆 tokenizer；规划模型与正文模型不同，可能存在实际 token 数和最大上下文差异。
- **流式：** 开启只表示请求流式返回，中转站可能缓冲后集中返回。插件不修改正文的 stream 设置。

## 常见问题

**没有出字，一直显示生成中？** 先看规划状态。手动模式可能在等待「生成正文回复」；规划阶段可能在等待 API。检查错误和发送上下文。要排除插件影响，取消勾选启用，停止当前轮并刷新页面后再试。

**规划少了步骤，或正文没有遵循规划？** 先确认发送上下文中存在相关内容，再对照输出；有内容不等于模型一定执行。默认提示词不构成自动完整性校验，增大额度也不能保证解决模型遗漏。

**恢复了密钥备份却不能请求？** 普通设置备份不包含本地 IndexedDB 密钥。换浏览器、换酒馆地址或清理网站数据后，可能需要重新填写并保存。

**如何反馈问题？** 提供插件和酒馆版本、生成类型、自动/手动模式、复现步骤及脱敏错误。说明规划/正文是否启用流式，是否同时使用变量或模板插件。不要公开 API Key；聊天全文不是默认必需材料。

## 开发与验证

```sh
npm test
npm run check
```

`tests/browser-check.mjs` 使用本地模拟酒馆和假 API，覆盖方案保存、手动正文、取消、楼内关联、提示词编辑、样式隔离、窗口交互和窄屏布局。运行它需要 Playwright 及浏览器，可通过 `PLAYWRIGHT_MODULE_PATH` 与 `BROWSER_EXECUTABLE` 指定本机路径。

当前新增的手动等待兼容修正已加入自动化回归；真实酒馆中新版手动流程及不同插件组合仍需进一步验收。私人预设不随仓库发布。

源码位于 `src`，入口为 `index.js`。历史版本见 [CHANGELOG.md](CHANGELOG.md)，扫描核心来源与许可说明见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。
